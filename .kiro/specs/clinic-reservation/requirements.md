# Requirements Document: clinic-reservation

**ステータス**: approved
**フィーチャー**: 病院・クリニック向け Web 予約と現在の待ち時間表示
**作成日**: 2026-10-10

---

## Introduction

病院・クリニックの患者が Web から診察予約を行え、来院前・来院中に「現在の待ち時間」を確認できるシステム。
電話・窓口対応の削減と、待合室の混雑緩和を目的とする。認証は既存 `user-auth` フィーチャーを前提とする。

**確定事項**: 医師指名可 / 当日受付（予約なし）あり / 電子カルテ・既存受付システムとは連携しない / 通知あり
**未確定事項**: 通知チャネル（初期はメール、SMS・LINE は将来検討）/ 初診の扱い

---

## Requirements

### Requirement 1: 診療科・医師・空き枠の検索

**Objective**: As a 患者, I want to 診療科・医師・日付から空き枠を探せる, so that 都合の良い時間に予約できる.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-001-AC-1 | WHEN 患者が診療科と日付を指定する THEN システムは予約可能な枠を時刻順に表示する | Must |
| REQ-001-AC-2 | WHEN 医師を指名する THEN システムはその医師の枠のみを表示する | Must |
| REQ-001-AC-3 | WHEN 枠が満席・休診・受付締切後である THEN システムはその枠を選択不可として表示する | Must |

---

### Requirement 2: Web 予約

**Objective**: As a 患者, I want to Web から診察予約を確定できる, so that 電話せずに受診できる.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-002-AC-1 | WHEN ログイン済み患者が空き枠・来院区分（初診/再診）・症状メモを送信する THEN システムは予約を確定し予約番号を発行する | Must |
| REQ-002-AC-2 | WHEN 同一枠に複数の予約が同時に送信された THEN システムは排他制御により定員を超える予約を確定せず、後続に HTTP 409 を返す | Must |
| REQ-002-AC-3 | WHEN 予約が確定した THEN システムは確認通知（日時・診療科・予約番号）をメールで送信する | Must |
| REQ-002-AC-6 | WHEN 予約の前日と、自分の順番が近づいた時点（あと数人）に達した THEN システムはリマインド通知を送信する | Should |
| REQ-002-AC-4 | 予約確定の応答は 3 秒以内に返す | Must |
| REQ-002-AC-5 | WHEN 患者が同一時間帯に既に別の予約を持つ THEN システムは重複予約を拒否する | Should |

### Requirement 8: 当日受付（予約なし）

**Objective**: As a 患者, I want to 予約なしでも当日の順番を取れる, so that 急な受診でも待ち状況が分かる.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-008-AC-1 | WHEN 患者またはスタッフが当日受付を登録する THEN システムは診療科の待機列の末尾に追加し受付番号を発行する | Must |
| REQ-008-AC-2 | 待機列は予約患者の予約時刻と当日受付患者の受付順を合わせた順序で管理し、待ち時間の算出に含める | Must |
| REQ-008-AC-3 | IF 受付終了時刻を過ぎている・定員に達した THEN システムは当日受付を拒否し理由を表示する | Must |

---

### Requirement 3: 予約の確認・変更・キャンセル

**Objective**: As a 患者, I want to 予約を確認・変更・キャンセルできる, so that 予定変更に対応できる.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-003-AC-1 | WHEN 患者がマイページを開く THEN システムは自分の予約一覧（今後・過去）を表示する | Must |
| REQ-003-AC-2 | WHEN 患者がキャンセル期限内に予約をキャンセルする THEN システムは枠を解放し通知を送信する | Must |
| REQ-003-AC-3 | WHEN キャンセル期限を過ぎている THEN システムはキャンセル不可とし、医療機関への連絡方法を案内する | Should |
| REQ-003-AC-4 | WHEN 患者が日時を変更する THEN システムは新枠の確保と旧枠の解放を原子的に行う | Should |

---

### Requirement 4: 現在の待ち時間表示

**Objective**: As a 患者, I want to 現在の待ち時間を確認できる, so that 来院タイミングを調整できる.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-004-AC-1 | WHEN 誰かが待ち時間ページを開く THEN システムは診療科ごとの現在の待ち人数と推定待ち時間（分）を、未ログインでも表示する | Must |
| REQ-004-AC-2 | システムは待ち時間を直近の診察実績（平均診察時間）と待ち人数から算出する | Must |
| REQ-004-AC-3 | WHILE 待ち時間ページが開かれている THE システムは 30 秒以内の間隔で表示を自動更新する | Must |
| REQ-004-AC-4 | WHEN 予約済み患者が自身の予約詳細を開く THEN システムは自分の順番（あと N 人）と呼出見込み時刻を表示する | Should |
| REQ-004-AC-5 | IF 待ち時間を算出できない（診療開始前・休診・診察実績が3件未満かつ標準診察時間も未設定）THEN システムは「算出不可」と理由を表示し、数値を推測表示しない。診察実績が3件未満でも管理者設定の標準診察時間がある場合は、それを用いて算出し「標準時間による目安」と明示する | Must |
| REQ-004-AC-6 | 待ち時間表示は目安である旨の注記を併記する | Must |

---

### Requirement 5: 受付・診察進行の管理（スタッフ向け）

**Objective**: As a 受付スタッフ, I want to 来院受付・呼出・診察完了を記録できる, so that 待ち時間が正確に算出される.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-005-AC-1 | WHEN スタッフが患者の来院受付を記録する THEN システムはその患者を待機列に追加する | Must |
| REQ-005-AC-2 | WHEN スタッフが呼出・診察開始・診察完了を記録する THEN システムは待機列と診察実績を更新し、待ち時間表示へ反映する | Must |
| REQ-005-AC-3 | WHEN スタッフが休診・臨時休診・医師不在を設定する THEN システムは該当枠を予約不可にし、既存予約者へ通知する | Must |
| REQ-005-AC-4 | スタッフ機能はロールベースで制限し、患者は利用できない | Must |

---

### Requirement 6: 枠・診療スケジュール管理（管理者向け）

**Objective**: As a クリニック管理者, I want to 診療科・医師・診療時間・枠数を設定できる, so that 運用に合わせた予約受付ができる.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-006-AC-1 | WHEN 管理者が診療時間・枠の長さ・定員を設定する THEN システムは該当日の予約枠を生成する | Must |
| REQ-006-AC-2 | WHEN 管理者が予約受付期間・キャンセル期限を設定する THEN システムは以降の予約に適用する | Should |

---

### Requirement 7: 個人情報・医療情報の保護

**Objective**: As a 患者, I want to 自分の情報が適切に保護される, so that 安心して利用できる.

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-007-AC-1 | 待ち時間の公開表示には個人を特定できる情報（氏名等）を含めない | Must |
| REQ-007-AC-2 | 症状メモ等の要配慮個人情報は、本人と権限を持つスタッフ以外が参照できないようアクセス制御する | Must |
| REQ-007-AC-3 | 通信は TLS で暗号化し、個人情報へのアクセスを監査ログに記録する | Must |
| REQ-007-AC-4 | 個人情報保護法および医療情報システムの安全管理ガイドラインに準拠する | Must |

---

### Requirement 9: 外部システム非連携

#### Acceptance Criteria

| AC-ID | EARS 記法 | 優先度 |
|-------|----------|-------|
| REQ-009-AC-1 | システムは電子カルテ・既存受付システムに依存せず、予約・待機列・診察実績を自システム内のみで管理する | Must |
