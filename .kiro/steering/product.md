# Product Context Steering

## プロダクト概要

**病院・クリニック向け予約システム（booking）**

患者が Web から診察予約を行え、現在の待ち時間を確認できるサービス。
医療機関の電話・窓口対応を減らし、待合室の混雑を緩和する。

## 対象ユーザー

| ロール | 説明 |
|--------|------|
| **患者** | 診察予約・待ち時間確認を行う。スマートフォン・PC から操作する |
| **受付スタッフ** | 来院受付・呼出・診察完了を記録し、休診設定を行う |
| **クリニック管理者** | 診療科・医師・診療時間・枠数・キャンセル期限を設定する |
| **システム管理者** | プラットフォーム全体の運用担当者 |

## ビジネスゴール

- Web 予約により電話・窓口対応を削減する
- 現在の待ち時間を公開し、来院タイミングの調整と待合室の混雑緩和を実現する
- ダブルブッキングをなくす

**主要 KPI（想定）**:
- 予約完了率
- ダブルブッキング発生件数: 0 件
- 予約操作の完了時間: 3 分以内
- 待ち時間表示の更新遅延: 30 秒以内

## スコープ（In / Out）

### In（対応する）
- 診療科・医師（指名可）・日付での空き枠検索と Web 予約
- 予約の確認・変更・キャンセル
- 当日受付（予約なしの来院・順番受付）
- 診療科ごとの現在の待ち人数・推定待ち時間の公開表示（未ログイン可）
- 受付スタッフによる来院受付・呼出・診察完了の記録
- 予約確認・変更・休診などの通知
- 診療スケジュール・枠の管理
- ユーザー認証（`user-auth` フィーチャー）

### Out（対応しない）
- 電子カルテ・レセプト・既存受付システムとの連携（本システム内で完結する）
- オンライン診療、決済処理
- モバイルネイティブアプリ（Web のみ）
- 多言語対応（日本語のみ）

## 主要な制約

| 種別 | 内容 |
|------|------|
| **技術** | 予約枠の同時書き込み制御（排他ロック）が必須 |
| **技術** | 待ち時間の精度は受付スタッフの操作記録に依存する。算出不能時は推測値を出さない |
| **ビジネス** | キャンセル期限・受付期間は医療機関ごとに設定可能にする |
| **セキュリティ** | 症状メモ等の要配慮個人情報は本人と権限スタッフのみ参照可。待ち時間の公開表示に個人情報を含めない |
| **性能** | 予約確定は3秒以内に応答すること |
| **法的** | 個人情報保護法、医療情報システムの安全管理ガイドラインに準拠 |
