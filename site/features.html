機能

患者・受付・管理者、それぞれに必要な機能。

役割ごとに画面を分け、見える情報も分けています。権限の判定は画面ではなく、サーバー（API）が行います。

患者さん

ログインなしで待ち時間、ログインして予約。

待ち時間ボード

診療科ごとに、お待ちの人数と待ち時間の目安を表示します。診察実績が足りないときや診療時間外は、理由だけを表示し、数字は出しません。

予約

診療科・医師（任意）・日付から、空き枠を一覧。満席・休診・受付締切後の枠は、理由つきで選べない状態になります。初診／再診と症状メモを添えられます。

マイページ

予約の確認、日時の変更、キャンセル。キャンセル期限を過ぎると、画面上で案内します。

順番の確認

来院受付後は「前に何人」と呼出の見込みが分かります。順番が近づくと通知（メール連携後）が届く設計です。

当日受付

予約なしでも、当日受付で待機列に並べます。診療科ごとに締切時刻と定員を設定できます。

アカウント

新規登録、ログイン、パスワードの再設定。ログイン状態は HttpOnly Cookie のトークンで維持します。

受付スタッフ

予約も当日受付も、ひとつの列で。

当日の予約

その日の予約を診療科ごとに一覧。患者さんが来たら、ワンクリックで来院受付。

待機列

受付順に並び、呼出 → 診察開始 → 診察完了と進めます。予約は予約時刻と来院時刻の遅いほうで並びます。

当日受付の代行

電話や窓口で受け付けた方を、アカウントなしでも登録できます。氏名はスタッフ画面にだけ表示します。

休診の設定

医師の不在や臨時休診の期間を指定すると、該当する枠を受付停止にし、予約済みの方へ通知を作ります。

クリニック管理者

診療スケジュール

医師ごとに、曜日・開始／終了・1枠の長さ・定員を設定。午前と午後のように、同じ曜日に複数の時間帯を置けます（重なりは保存前に検出）。保存すると枠が自動生成されます。

基本設定

予約受付期間（日数）、キャンセル期限（分）、診療科ごとの標準診察時間・当日受付の締切・定員。

待ち時間の計算

数字を出すときは、根拠があるときだけ。

実績ベース

その日の診察完了の実績から、1人あたりの診察時間を求め、前に並ぶ人数と診察中の医師数から目安を出します。

標準時間ベース

実績がまだ少ないときは、診療科ごとの標準診察時間を使い、「目安」であることを表示します。

出さない場合

診療開始前・休診中・診察実績が不足しているときは、理由を表示するだけで、推測の数字は出しません。

安全面の考え方

観点内容
権限患者／スタッフ／クリニック管理者の3役割。画面の出し分けは利便性のためで、認可の判定は API が行います。
個人情報氏名・症状メモは、本人とスタッフにだけ返します。公開の待ち時間 API には個人を特定できる情報を含めません。
監査ログスタッフによる氏名・症状の閲覧や、重要な操作を記録します。
二重予約・定員超過枠の定員は単一の条件付き更新で守り、データベースの制約を最終防壁にしています。
連続ログイン失敗・過剰アクセスログインや公開 API には、回数制限をかけています。
レビュー敵対的なセキュリティレビュー（S1〜S5）の指摘に対応済みです。外部の第三者による診断は、まだ受けていません。
