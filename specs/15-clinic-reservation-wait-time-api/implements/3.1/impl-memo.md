# 実装判断メモ: 15-clinic-reservation-wait-time-api / 3.1

## 採用したアプローチ

- **整数演算で切り上げ**: 平均を秒に丸めてから `(n×平均 + 分母−1) ÷ (医師数×60)`。浮動小数の誤差（30.0000001 → 31 分）を避ける。
- **算出不可の理由を 3 つに分けた**: 診療時間内なのに診察できる医師がいない = 臨時休診(closed)、今日この後に診療が始まる = 診療開始前(before_hours)、それ以外 = closed（終了後・休診日）。このため「休診を無視した診療時間内の医師数」と「この後に始まる医師数」のクエリを追加。
- **実績が足りない間は標準診察時間、無ければ算出不可**（REQ-004-AC-5 を、tasks の「標準時間で算出」に合わせて明確化済み）。待っている人が 0 人なら 0 分は事実なので返す。
- **外れ値の上限（1 件 3 時間）**: スタッフの完了押し忘れで平均が数倍になり、待ち時間が極端に長く表示されるのを防ぐ。上限値は運用で調整する余地あり。
- **キャッシュは算出中ロック**: 同時アクセスが集中しても DB に行くのは 1 回。失敗は保存しない。`updated_at` は算出時刻（キャッシュ中は古いまま）なので、フロントが鮮度を表示できる。
- **公開 DTO はポインタ + omitempty**: 算出不可のときは数値のキー自体を出さない（0 分と区別する）。
- **順番の見込み**: 待機中のみ `now + 前の人数ぶんの待ち時間`。見込みを出せないときは null。人数（ahead_count）は常に返す。

## 検討した代替案

| 代替案 | 不採用の理由 |
|---|---|
| 平均ではなく中央値 | 要件が平均。外れ値は上限で対処 |
| 医師別の待ち時間 | 要件は診療科単位。指名予約の別列は将来 |
| キャッシュをフロントのみに | 公開 API の DB 負荷を抑えるためサーバー側も必要 |
