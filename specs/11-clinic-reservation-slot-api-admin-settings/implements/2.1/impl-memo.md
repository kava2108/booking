# 実装判断メモ: 11-clinic-reservation-slot-api-admin-settings / 2.1

## 採用したアプローチ

- **診療日・診療時間は JST の固定オフセット**（`time.FixedZone`）。コンテナに tzdata が無くても動く。単一医療機関・国内運用が前提。
- **枠は満席・休診・締切後・受付期間外も理由つきで返す**（REQ-001-AC-3「選択不可として表示」）。優先順位は closed > past_cutoff > outside_window > full。公開応答に capacity / booked_count は含めない。
- **枠生成は冪等**（`ON CONFLICT DO NOTHING`）。生成後に**既存の休診期間を再適用**する（休診設定後に生成された枠が open のまま予約できてしまう問題の防止）。保存時と 1 時間ごとのジョブの両方で実行。
- **スケジュール保存は「置換」**。検証エラーのときは何も変更しない。既に予約済みの枠は削除しない（新規生成のみ）。
- **設定の診療科項目は全項目の置換**（省略 = 未設定 NULL）。医療機関設定は部分更新（省略は現在値維持）。診療科が不明なら全体をロールバック。
- **OpenAPI の契約チェックを統合テストに組み込み**、実応答をスキーマで検証。これで 400 / 500 の未定義が見つかり定義を追加。
- **ネストしたバリデーションのフィールド名**（`schedules[0].weekday`）を返すよう validator を拡張。

## 検討した代替案

| スケジュール変更時に旧スケジュールの未予約枠を削除 | 予約の取り合い・整合の検討が必要。TODO |
