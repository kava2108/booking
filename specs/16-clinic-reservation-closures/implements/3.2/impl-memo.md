# 実装判断メモ: 16-clinic-reservation-closures / 3.2

## 採用したアプローチ

- **すべて同一 Tx**: 休診の作成、枠の closed 化、通知の登録、監査ログ。どれか 1 つでも失敗すれば全体が巻き戻る（監査ログの FK 違反を起こして確認）。
- **通知は「今回新たに閉じた枠」の予約者だけ**: `CloseSlots` が返す ID（open → closed に変わった枠）で絞る。同じ休診の再送や重なる休診で、同じ予約者に二重通知しない。
- **予約は自動キャンセルしない**: 要件は「予約不可にし、既存予約者へ通知」。キャンセルは患者の意思確認が要るため、通知で再予約を案内する。
- **休診の理由（自由記述）は通知に載せない**: スタッフが意図せず書いた情報（例: 個人的な事情）が全患者に送られるのを防ぐ。定型文のみ。理由は DB に記録（スタッフ用）。
- **監査ログはサービス内で同一 Tx に記録**: ミドルウェア方式だと、検証エラーでも記録される・Tx と別になる問題があるため（#13 の教訓）。
- **終了が現在より後であれば、開始が過去でも可**: 診察中に急な休診を設定する運用を許す。
- 待ち時間への反映は #15 の「休診中の医師を除く」クエリで自動的に効く。

## 検討した代替案

| 代替案 | 不採用の理由 |
|---|---|
| 休診枠の予約を自動でキャンセル | 患者への確認なしの取消は不適切。要件外 |
| 通知本文に理由を入れる | 意図しない情報の送信リスク |
| 重複期間の休診を拒否 | 全体休診と医師休診の重なりなど判定が複雑。冪等な通知で十分 |
